# SpaceTerm Mobile

The native iOS and Android companion app for [SpaceTerm Desktop](https://github.com/sadiksaifi/spaceterm).

## Architecture

- Follow **vertical slices**: organize by feature, co-locating related UI, state, and behavior. Keep Expo Router routes thin.
- Keep behavior, invariants, and cleanup in deep modules with narrow interfaces. Expose intentional operations and typed recoverable failures.
- Keep product policy portable. Access frameworks, services, and platform capabilities through constructor-injected adapters only when justified by replaceability or locality.
- Prefer feature-local code over premature sharing. Every line and abstraction we own is maintenance.
- Keep performance-critical terminal I/O, input, and rendering native, outside the JavaScript hot path.

Illustrative structure, not a prescribed layout:

```text
src/
├── app/
│   └── <feature>.tsx       # Route
└── features/
    └── <feature>/
        └── screen.tsx      # Implementation
```

## Platform experience

- Target **iOS and Android only**. iOS follows the [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/) in the look of iOS 26 and later. Android follows [Material 3 Expressive](https://m3.material.io/).
- iOS 26 and iOS 27 differ in details, and so do Android releases. Verify a component on the newest simulator or emulator, and build with system components so each OS version draws its own.
- Respect each platform's native appearance, navigation, interactions, typography, motion, accessibility, and adaptive behavior. Prefer `@expo/ui` with SwiftUI/Jetpack Compose. Share logic, not forced visual uniformity.
- Read `DESIGN.md` before building or changing a screen, a control, or user-facing text.

## Documentation

- Document only intent and constraints that code, configuration, or UI cannot express. State facts once; reference their source of truth.
- Keep plans and validation reports in issues or PRs. Avoid documentation that merely describes the current implementation.

## Tooling

- `.mise.toml` owns tool versions; `package.json` owns dependencies and scripts. Inspect them instead of duplicating their contents.
- Use `pnpm` and project scripts. Install Expo/RN packages with `pnpm expo install <package>` and dev tools with `pnpm add -D <package>`.
- Use `*.test.ts` for Vitest and `*.test.tsx` for Jest (`jest-expo`). Diagnose dependency/configuration issues with `pnpm dlx expo-doctor`.
- Before declaring a task done, run `pnpm fmt:check`, `pnpm lint`, `pnpm typecheck`, and `pnpm test`.

## Expo APIs

**Verify, never assume.** Before using Expo, EAS, or React Native APIs:

- Read the installed Expo SDK version from `package.json`, then consult `https://docs.expo.dev/versions/v<major>.0.0/`.
- Use https://docs.expo.dev/llms.txt to find relevant API documentation. Verify compatibility rather than relying on training data.

## Builds and distribution

- Use `pnpm ios` / `pnpm android` for local development builds.
- `ios/` and `android/` are generated by prebuild and gitignored. Configure native behavior in `app.config.ts` and config plugins.
- EAS (cloud builds, signing, submission, OTA updates) is not set up yet. Set it up only on request, then run `eas` from the version pinned in `.mise.toml`. Refer to [EAS docs](https://docs.expo.dev/eas/) for workflow details.
